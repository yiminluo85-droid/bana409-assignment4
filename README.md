# 北辰分析｜销售脉搏

本仓库包含 BANA409 作业 4 的 Streamlit 数据应用，以及配套的手机以旧换新定价分析 Notebook。

## 运行仪表板

```bash
uv sync
uv run streamlit run app.py
```

项目使用 Python 3.14。Streamlit Cloud 可以通过 `requirements.txt` 安装精简的部署依赖；本地运行完整 Notebook 时，可使用 `pyproject.toml` 和 `uv.lock` 复现分析环境。

## 第一步：数据集与决策者

本项目使用 Kaggle 上的 [Sales Forecasting 数据集](https://www.kaggle.com/datasets/rohitsahoo/sales-forecasting)。它是一个约 2.1 MB 的表格型 CSV 文件，包含某美国大型零售商的 9,800 条订单明细。每行代表订单中的一种商品，字段包括订单日期、发货日期、客户细分、区域、产品类别和销售额。数据覆盖 2015 年 1 月至 2018 年 12 月。

仪表板的目标用户是**区域销售经理**，而不是公司的所有员工。

## 第二步：为什么需要仪表板

区域销售经理每周一都要回答三个重复出现的问题：销售额是否正在下降、哪个区域或产品类别造成了变化，以及下周应把管理注意力放在哪里。如果某个区域或类别的销售额走弱，经理将与对应团队检查销售管道和促销计划。

如果没有仪表板，经理必须反复整理订单导出文件并手工比较各区域，不仅会拖慢例会，还容易出现日期口径不一致的问题。仪表板也比每周邮件更合适，因为经理需要在会议中切换区域、类别和年份；单一告警只能说明出现问题，却不能解释问题来自哪里。

## 第三步：展示内容与删减原则

页面顶部只保留三个核心指标：筛选后的销售额、去重订单数和配送时间中位数。它们分别回答商业规模是否稳定、订单量是否变化以及履约是否变慢。

第一张图展示月度销售趋势，用于判断变化从何时开始；第二张图按区域和产品类别拆分销售额，用于定位变化来源。区域、产品类别和订单年份是唯一的筛选项，因为它们直接对应经理的每周决策。页面底部额外提供销售额最高的产品子类别表，便于必要时继续下钻。

本项目不展示客户姓名，因为每周决策关注的是区域和类别，而不是具体个人，显示姓名只会增加无关细节和隐私风险。项目也删除了邮政编码地图和单品排名：数据中没有区域目标、产品成本和库存，保留这些视图容易诱导用户做出数据无法支持的判断。

数据的主要局限是 `Sales` 表示收入而不是利润，文件中也没有退货与产品成本。因此，应用始终将该指标标记为“销售额”，并明确提醒不能将其解释为利润。

页面顺序遵循决策过程：先看总体指标，再看原因分析，最后查看明细。如果删去明细表，经理仍能完成主要决策；如果删去趋势图或区域类别图，仪表板将无法解释变化。

## 第四步：更新与复盘频率

在实际生产环境中，订单和发货数据应在交易系统每日关闭后进行夜间更新。区域销售经理应在每周一销售例会前查看仪表板。实时更新会增加成本，却不会改变以周为单位的管理决策。

建议持续跟踪各区域最近四周的销售额。如果某一区域相较前四周下降超过 10%，应在当天检查该区域的销售管道和促销安排。若数据延迟一周，经理可能会在例会上追查一个已经恢复的问题，也可能完全错过新出现的下滑。

当前应用明确标注其数据为 2015 年 1 月至 2018 年 12 月的 Kaggle 固定快照。

## 文件说明

- `app.py`：Streamlit 销售仪表板。
- `data/superstore_sales.csv`：从 Kaggle 下载的仪表板数据集。
- `phone-trade-in.ipynb`：第二部分的数据分析、模型比较和书面回答。
- `analysis.py`：用于复核 Notebook 结果的确定性分析脚本。
- `outputs/`：分析脚本生成的结果表和图表。
- `requirements.txt`：部署仪表板所需的最小依赖清单。
